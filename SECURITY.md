# Security policy

## Reporting a vulnerability

Do not disclose exploitable vulnerabilities, credentials or personal data in public
issues or pull requests.

Use the repository's Security tab and **Report a vulnerability** option when
GitHub private vulnerability reporting is enabled. If that option is unavailable,
ask a repository maintainer for a private reporting channel without publishing
vulnerability details. This policy does not itself enable private reporting.

Include the affected component and commit/version, reproduction steps using test
data, expected impact and any suggested mitigation. Remove passwords, tokens,
student information and other personal data from logs or screenshots.

## Scope and handling

The project is under active development. Reports concerning the current main
branch are the primary focus; no long-term release support schedule is declared.
Maintainers will assess reports and coordinate fixes and disclosure with reporters.
No fixed response deadline is promised.

Test only systems and accounts you are authorized to access. Do not access other
users' records, exhaust paid model credits or disrupt hosted services.

If a credential has been exposed, its owner should revoke or rotate it promptly.
Deleting it from the latest commit alone does not remove it from Git history.
